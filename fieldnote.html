Operational Discovery · Project Case Study

Fieldnote Discovery App

A discovery tracking and standardization system for turning rough enterprise notes into a structured operating model that can be reviewed, enriched, reused, and passed downstream into demo strategy.

Launch live app ↗See project walkthrough

The problem

Enterprise discovery often gets trapped in chronological call notes. Important context is present, but it is difficult to tell what is actually known, what is assumed, where the operating gaps are, or what needs to be validated before a demo or pilot.

What breaks

Teams confuse activity with understanding. A completed discovery call can create the impression that discovery is complete even when critical context around ownership, flow, exceptions, proof, or decision rights is still missing.

What I wanted instead

A reusable discovery model that separates facts, hypotheses, unknowns, and source material, then makes missing context visible enough to deliberately return to it.

How I use it

Fieldnote is designed as an iterative loop, not a one-time form.

01

Export

Start with the structured discovery template.

02

Populate

Add raw notes from calls, workshops, emails, or documents.

03

Reload

Load the populated file back into Fieldnote.

04

Find gaps

Review what is known, what is assumed, and what is missing.

05

Refine

Fill the gaps and carry the structured output downstream.

What it standardizes

The app organizes discovery around reusable concepts rather than around the order in which questions happened to be asked.

Operating model

Outcome, trigger, ownership, flow, decisions, variance, coordination, exceptions, proof controls, and visibility / feedback.

Evidence quality

Facts, hypotheses, unknowns, and source notes are kept distinct so uncertainty is explicit instead of buried inside polished summaries.

Outputs

The value is not only cleaner notes. Fieldnote creates portable context that can be reused in the next step of the sales process.

Output 01

Structured discovery record

A durable view of the customer's operating reality: what they are trying to change, how work happens today, where decisions and exceptions occur, and what still needs validation.

Output 02

Demo-ready context

A reusable handoff into my downstream demo workflow so the script can reflect the buyer's goals, personas, process, proof requirements, and unresolved questions.

Design principles

Discovery is iterative

A call ending does not mean understanding is complete.

Structure exposes uncertainty

The system should make assumptions and unknowns visible rather than hiding them.

Outputs should travel

Discovery becomes more valuable when its structure can directly inform demos, pilots, and value hypotheses.
